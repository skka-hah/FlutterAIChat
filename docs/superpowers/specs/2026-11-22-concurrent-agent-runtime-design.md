# 多会话并发与 Agent 运行时设计

> 设计草案。本文件定义目标行为和验收条件。

## 目标与范围

FlutterAIChat 在同一个应用进程内可以同时推进多个会话的 agent 任务。用户切换会话后，原会话继续生成和执行工具。用户回到该会话时能看到期间的进度、结果或待处理的审批。

第一阶段交付多会话并发。每个会话同时最多有一个活跃的主运行，同一会话的追加输入延续 Steer 和 Queue 语义。运行时以单次执行为单位组织状态，为同一会话内的主 agent 与子 agent 并发预留边界。首版的执行范围是存活的应用进程，进程重启后通过持久化记录恢复展示和中断状态。

## 当前边界

[`ChatSendCoordinator`](../../../lib/controllers/chat_send_coordinator.dart) 根据共享的发送 phase 决定是否把新请求排队。[流订阅、取消回调和流式预览](../../../lib/providers/chat_ui_providers.dart) 绑定到当前聊天流程。两者需要共同迁移，否则新增第二条执行流仍会覆盖原会话的控制状态或预览。

[`TurnHarness`](../../../lib/services/turn_harness.dart) 已按 `turnId` 读取 transcript，事件仓库也按 turn 管理写入。可复用现有执行循环、工具执行与模型适配。模型历史仍由 [`SessionContextService`](../../../lib/services/session_context_service.dart) 按 `groupId` 组装，子运行接入时需要显式指定自己的上下文范围。现有工具批次并发发生在单个 turn 内，父循环会等待该批次结束。

## 身份与模块职责

| 概念 | 用途 |
| --- | --- |
| `groupId` | 会话归属，用于用户可见的聊天、会话设置和主会话历史 |
| `turnId` | 持久化的执行记录标识，用于查找 step 和 append-only transcript |
| `runId` | 单次活动执行的标识，用于调度、取消和回调归属。恢复已暂停的 turn 时为新执行分配新的 `runId` |
| `parentTurnId`、`parentToolCallId` | 子任务的持久化归属，用于在父 turn 恢复后关联委派与结果，首版主运行无需填写 |

**应用级运行管理器**负责启动执行、登记活动运行、分配并发额度、管理订阅和定向取消。它维护 `runId → 活动执行` 和 `groupId → 主 turn` 两份索引。前者按执行清理，后者保留到主 turn 终止，包含等待确认、等待回答或排队恢复期间。登记与校验同会话占用必须在首次异步执行之前完成，避免快速双击启动两次主运行。

**`TurnHarness`** 继续负责执行 planner、工具和最终回复。运行开始时捕获目标会话、配置和上下文范围。回调及工具确认都通过显式 ID 路由，运行过程中不依赖 UI 当前选中的会话。共享的模型客户端和工具注册表可继续复用，请求状态和取消信号随各自运行传递。

**发送协调器与 UI 投影**负责准备用户输入、向运行管理器提交请求，以及展示目标会话的状态。真值事件按原 `turnId` 和 `groupId` 持久化。流式草稿、工具卡和审批状态按会话与运行归属投影。切换页面只切换 UI 订阅。切回时先读取该会话的最新投影，再接收后续增量。

## 调度与生命周期

- **入队与并发。** 同一会话的 Steer 只在当前主 turn 的下一次 planner 调用前消费，Queue 在主 turn 结束后启动。不同会话按就绪顺序独立进入共享并发池。首版默认允许两个执行同时推进，超出额度的请求排队，覆盖多会话验收场景。等待用户审批或回答时释放执行额度，恢复时重新获取，同时保留会话的主 turn 占用。
- **停止与清理。** 取消请求必须指定目标运行。停止时标记取消并向该运行的模型流及支持取消的工具传播取消信号。对于已发出且无法撤回的外部操作，记录其实际结果，禁止其迟到回调继续推进已取消的循环。终止操作必须幂等，迟到回调不得覆盖终态或清除新运行的订阅。
- **审批与恢复。** 确认、拒绝和回答必须校验 `groupId`、`turnId` 和工具调用标识。恢复沿用既有 transcript 和 turn 记录，重新登记执行。多个会话可各自保留待处理交互。
- **进程重启。** 已提交的消息和事件继续可读。启动时将没有存活执行的运行中记录收敛为中断状态，保留已有输出。仍可恢复的待确认记录依现有确认流程恢复，未开始的内存队列随进程结束清理。运行时不会自动重放曾经发出的工具调用。

## Subagent 接入边界

子任务通过同一运行管理器启动，拥有自己的 `runId`、`turnId`、预算和事件流，持久化关联发起它的父 turn 与工具调用。子任务上下文由角色提示词、委派输入和显式材料组装，子 transcript 不进入主会话历史。模型能看到的工具和实际执行权限都取角色允许范围与父会话权限的交集。

异步委派先返回子任务 ID。子任务完成后，结构化结果写入父 turn 的收件队列，供父 agent 在下一次 planner 调用前消费。若父任务需要等待结果，则显式挂起并释放执行额度，以便子任务取得额度。结果按子任务 ID 去重，父任务进入终态后不再推进其循环。取消父任务时传播到仍活动的子任务，子任务失败则作为委派结果交回父任务。委派工具和子任务 UI 在多会话并发通过验收后接入。

## 验收条件

| 场景 | 可观测结果 |
| --- | --- |
| A 流式输出时切到 B 并发消息 | B 在 A 完成前发出模型请求。切回 A 可见 A 在离开期间的输出 |
| A、B 同时生成，停止 A | A 保留已产生内容并进入取消终态，B 继续生成。A 的迟到回调不会修改 B 或 A 的后续运行 |
| A 等待工具确认，B 继续运行 | B 的工具和回复可正常完成。确认 A 只恢复 A 的指定工具调用 |
| 对同一会话快速发送两次并交错产生事件 | 只创建一个活跃主 turn，后续输入按 Steer 或 Queue 处理。各会话的 transcript 和时间线只包含归属于自己的事件 |
| 并发池达到上限 | 新请求显示排队。现有执行完成或挂起后，就绪请求获得额度。取消排队请求后它不发起模型调用 |
| 交错执行期间退出并重启 | 已写入的数据按会话恢复。原来运行中的任务显示中断，已发出的工具调用不重复执行 |
| 后续接入子任务后，父、子同时运行 | 子任务未结束时，父任务可以发起另一轮模型调用。子任务结果只回到发起委派的父 turn，且只被消费一次 |

用可控的模型流验证请求实际重叠，避免仅凭 UI 的两个运行标记判断并发。通过协调器或集成测试对照事件落库与 UI 投影，并在界面验证切换会话、停止和审批。
